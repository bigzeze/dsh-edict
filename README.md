# ⚔️ dsh-edict · 三省六部

> 把中国古代「三省六部」的朝廷制度，搬进 DeepSeek Harness（DSH）的多 Agent 协作。
> 复杂任务不再是一个 AI 闷头干，而是一道**旨意**走完「太子分拣 → 中书规划 → 门下审议（可封驳）→ 尚书派发 → 六部并行执行 → 回奏」的完整流程，全程留痕、可观测、可叫停。

**简体中文** · [English](README.en.md)

---

## 它解决什么问题

普通的多 Agent 协作往往「靠自觉」：模型想起来才拆任务、没人把关方案质量、子任务失败了看板上却一切正常、你也没法中途干预。dsh-edict 用一套**制度性的状态机**把流程变成硬约束：

- **强制审议闸门**：方案必须经「门下省」审议，不合格就**封驳**打回中书省重做，不能跳过。
- **全程留痕**：每一次流转、封驳、派发、部务完工都写入流转链，事后可审计。
- **实时军机处看板**：浏览器里一张看板，旨意到了哪个阶段、六部各干到哪、谁卡住了，一目了然。
- **可干预**：你随时能**叫停 / 恢复 / 取消**任何一道在办旨意。
- **失败不掩盖**：某个部的 Agent 执行报错，看板自动标红，有失败部务不得回奏。

---

## 与原版 edict 的关系

本插件的灵感来自 [cft0808/edict](https://github.com/cft0808/edict)——一个基于 OpenClaw、用 12 个常驻 Agent + IM 消息模拟朝廷的项目。dsh-edict 把它的**制度思想**移植为 DSH 原生插件：

| 维度 | 原版 edict (OpenClaw) | dsh-edict (本插件) |
|---|---|---|
| 运行形态 | 12 个常驻 Agent + SOUL.md 人格 | 任务级临时 subagent / workflow，无常驻进程 |
| 状态流转 | Python 脚本写 JSON | 插件内置状态机，非法流转直接拒绝 |
| 看板 | FastAPI + React 独立服务 | DSH 内置 HTTP 路由 + 侧边栏原生入口 |
| 审批 | 消息约定 | 门下省审议为强制工具闸门，封驳自动打回 |
| 集成 | IM（飞书 / Telegram） | DSH 工具、斜杠命令、技能、会话原生 |

## 安装

### 前置条件

- **DeepSeek Harness（DSH）** 已安装，且使用 `web` profile（`dsh web`）。
- **Node.js ≥ 20**。
- 本地链接安装需要 **pnpm** 在 `PATH` 中（DSH 用 pnpm 管理 profile 的插件依赖）。

### 方式一：本地链接安装（开发 / 试用，推荐先这么装）

在插件源码目录的**上级目录**执行，路径建议用绝对路径：

```bash
dsh plugin --profile web add link:/绝对路径/dsh-edict
```

例如源码放在 `/home/user/Desktop/dsh/dsh-edict`：

```bash
dsh plugin --profile web add link:/home/user/Desktop/dsh/dsh-edict
```

链接安装无需联网、改完源码重启即生效，适合开发与自托管。

### 方式二：从 npm 安装（发布后）

```bash
dsh plugin --profile web add dsh-edict
```

### 安装后：重启生效

插件在 `dsh web` 进程启动时加载，**安装 / 更新后需重启**：在运行 `dsh web` 的终端按 `Ctrl+C`，再重新运行 `dsh web`，然后刷新浏览器。

### 验证安装成功

重启后：

1. 侧边栏底部出现一个 **⚔️ 军机处** 按钮（窄边栏只显示 ⚔️ 图标）；
2. 浏览器直接访问 `http://127.0.0.1:<端口>/edict/` 能打开看板；
3. 会话中输入 `/edict` 能看到军机处状态摘要。

### 卸载

```bash
dsh plugin --profile web remove dsh-edict
```

## 快速开始

### 1. 下一道旨意（最自然的方式）

直接用自然语言交代一个**够复杂**的任务即可，例如：

> 「帮我做一个带登录的待办应用，要有前端、后端和部署文档。」

模型会按制度自动走流程：先**太子分拣**立旨建档，再派**中书令**出方案、**侍中**审议，准奏后由**尚书省**派发给六部并行执行，最后**回奏**。你也可以显式要求：「用三省六部做……」「下旨：……」。

> 💡 简单的问答、闲聊、改一行小 bug **不会**也不应该走这套流程——太子分拣这一步会把它们拦下，否则每句话都兴师动众。

### 2. 斜杠命令 `/edict`

| 用法 | 作用 |
|---|---|
| `/edict` | 查看军机处当前在办旨意摘要 |
| `/edict <你的需求>` | 把 `<需求>` 录为一道旨意并开始走流程 |

### 3. 军机处看板

两种打开方式：

- 点侧边栏底部的 **⚔️ 军机处** 按钮，在当前窗口弹窗查看；
- 浏览器直接访问 `/edict/` 独立页面。

看板顶部是统计（在办 / 叫停 / 今日完工 / 封驳次数 / 部务进度），中间按六个阶段分列，点任意卡片从右侧滑出**详情抽屉**（旨意、六部分派、当前进展、完整流转链）。被**叫停**的旨意会出现在顶部朱红警示条。第二个页签 **📜 奏折阁** 收录所有已回奏归档的旨意。

### 4. 叫停 / 恢复 / 取消

在看板详情抽屉里：

- **🛑 叫停**：把在办旨意挂起（进入「叫停」状态），模型会停止推进；若该旨意关联了长期目标，会一并暂停；
- **▶️ 恢复**：从叫停状态回到原阶段继续；
- **❌ 取消**：终止旨意（需先叫停）。

点击后指令会直接发进当前会话由模型执行；独立页面打开时则进入服务器队列，等模型下次取看板时处理。

## 工作流程与状态机

一道旨意的合法流转如下（非法跳转会被工具拒绝并提示合法去向）：

```
太子分拣 intake ──→ 中书规划 planning ──→ 门下审议 review
                                              │
                            封驳 reject ↺──────┤
                                              │ 准奏 approve
                                              ▼
                                        尚书派发 dispatching
                                              │
                                              ▼
                                         六部执行 doing ──→ (发回补充) ↺
                                              │
                                              ▼
                                        回奏审定 final_review
                                              │ 回奏
                                              ▼
                                           已完成 done
```

另有两个干预态：**叫停 blocked**（可恢复或取消）、**已取消 cancelled**（终态）。

门下省封驳最多来回两轮；仍不达标，流程会把分歧陈明请你裁断。

## 工具速查表

插件向模型注册 10 个 `edict_*` 工具（一般你无需手动调用，模型会按流程使用）：

| 工具 | 用途 | 关键参数 |
|---|---|---|
| `edict_issue` | 立旨建档（intake） | `title`*、`detail`、`goalId` |
| `edict_transit` | 通用状态流转 | `id`*、`to`*（目标状态）、`remark` |
| `edict_verdict` | 门下省审议 | `id`*、`verdict`*（`approve`/`reject`）、`opinions` |
| `edict_assign` | 尚书省派发六部 | `id`*、`items`*（`{ministry, task}`） |
| `edict_progress` | 报进展 / 更新清单 | `id`*、`doing`*、`checklist` |
| `edict_assignment` | 部务回报状态 | `id`*、`key`*、`status`*（`todo`/`doing`/`done`/`failed`）、`result` |
| `edict_complete` | 回奏归档（→done） | `id`*、`summary`*、`outputs` |
| `edict_control` | 叫停 / 恢复 / 取消 | `id`*、`action`*（`hold`/`resume`/`cancel`）、`note` |
| `edict_list` | 看板取数 | `status`（可选过滤） |
| `edict_show` | 取单道旨意完整流转链 | `id`* |

## 角色与六部

**决策三省**：

| 角色 | 职责 |
|---|---|
| 🤴 太子 | 消息分拣：闲聊直接回复，旨意提炼标题、立档 |
| 📜 中书省 | 接旨规划：理解需求、设计方案、拆解子任务、定验收标准 |
| 🔍 门下省 | 审议封驳：从可行性 / 完整性 / 风险 / 资源四维审查，准奏或封驳 |
| 📮 尚书省 | 派发协调：把子任务派给六部、并行推进、汇总回奏 |

**执行六部**：

| 部门 | 分管 |
|---|---|
| 💰 户部 | 数据、资源、核算：数据处理、报表、成本分析 |
| 📝 礼部 | 文档、规范、报告：技术文档、API 文档、规范制定 |
| ⚔️ 兵部 | 代码、算法、巡检：功能开发、Bug 修复、代码审查 |
| ⚖️ 刑部 | 安全、合规、审计：安全扫描、合规检查、红线管控 |
| 🔧 工部 | CI/CD、部署、工具：Docker、流水线、自动化 |
| 📋 吏部 | 人事、Agent 管理：子代理编排、权限维护、流程元任务 |

## 多 Agent 编排约定

插件注册了一个 **`edict` 技能**，模型遇到复杂任务时会自动按手册编排。关键点：

- **自动心跳**：插件监听 DSH 的 `workflow` / `subagent` / `goal` 生命周期事件，自动给看板写「开工 / 完工」心跳，无需 Agent 手动打卡。
- **label 约定**（让心跳能对号入座）：用 `workflow` fan-out 六部时，
  - workflow 的 `meta.name` 写成 `edict-<旨意编号>`；
  - 每个 agent 的 `label` 写成 `edict:<旨意编号>:<部门名>`（如 `edict:EDICT-20260827-001:兵部`）。
  - 不带编号的 workflow 事件会被严格忽略，不会污染别的会话。
- **goal 联动**：长任务可在建旨时传 `goalId`，看板显示 🎯 联动标记；叫停 / 恢复时提示模型同步暂停 / 恢复对应目标。
- **失败返工**：某个部的 Agent 报错（stopReason=error）会被自动标为 `failed`（看板红色），需排查后重做；有失败部务时模型不会进入回奏。

## 数据与文件

| 内容 | 位置 |
|---|---|
| 旨意 / 流转链 / 奏折数据 | `~/.dsh/dsh-edict/edict.json`（原子写入，终态旨意自动裁剪保留最近 200 条） |
| 看板页面 | 插件内置，HTTP 路由 `GET /edict/` |

| 服务端代码 | 插件包 `lib/` |
| 浏览器端代码 | 插件包 `client/`（手写 bundle，无构建步骤） |

## 故障排查

| 现象 | 原因与处理 |
|---|---|
| 侧边栏没有 ⚔️ 按钮 | 插件需重启 `dsh web` 才加载；确认装在 `web` profile；浏览器强刷（Ctrl+Shift+R）清缓存 |
| 看板显示「连接失败」 | 确认访问的是 `/edict/`；数据接口为 `/edict/api/board`（插件内部已用绝对路径）；检查 `dsh web` 是否在运行 |
| `dsh plugin add` 报 pnpm / ENOENT 错误 | 本地链接安装依赖 pnpm，请先安装 pnpm 并确保在 `PATH` |
| 无法用 `git+https://...` 安装 | 部分环境没有 git，请改用 `link:<本地路径>` 或 npm 包名安装 |
| 模型没走三省六部流程 | 简单任务本就不该走；需要时显式说「用三省六部做……」或用 `/edict <需求>` |
| 部务卡片一直「进行中」 | 若该部 Agent 报错会自动标红；否则检查 workflow 的 `meta.name` / agent `label` 是否遵守约定 |
